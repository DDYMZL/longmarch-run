## 4. 缺陷清单

### BUG-B1【严重】新增题目必现 500：`questions.id` 无自增

- **接口**：`POST /api/admin/questions`
- **现象**：管理端「题库维护 → 新增题目」填表保存，toast `Request failed with status code 500`；后端日志 `IntegrityError ... null value in column "id" ... NotNullViolation`。
- **复现**：任意合法题面（单选/判断均复现），HTTP 直连同样 500。
- **根因**（三方叠加）：
  1. `docker/init/001_schema.sql`（questions 表，16–24 行）：`id INTEGER PRIMARY KEY`，未用 `SERIAL`/identity，无默认值；
  2. `backend/app/models/models.py`：`Question.id = mapped_column(Integer, primary_key=True)` 未显式 `autoincrement`，SQLAlchemy 对单列整型主键默认按“数据库自增”处理 → INSERT 省略 id 列；
  3. openGauss 表实际无默认值 → 插入 NULL → NotNullViolation。
  - 对照组：同库 `route_nodes/users/daily_sport/lit_nodes/quiz_records` 均为 `SERIAL`，对应接口正常。
- **旁证**：显式指定 id 的 INSERT（python/psycopg2）成功，证明仅缺自增。
- **修复建议**：DDL 改为 `id SERIAL PRIMARY KEY`（或 `GENERATED BY DEFAULT AS IDENTITY`）并重建表；模型侧为 `Question`、`Organization` 显式补 `autoincrement=True/序列` 或与 DDL 对齐。存量表需 `DROP/重建` 或补默认值序列。
- **影响面**：题库无法新增，功能完全不可用（编辑/删除不受影响）。

### BUG-B2【严重】新增组织必现 500：`organizations.id` 同类缺陷

- **接口**：`POST /api/admin/orgs`
- **现象**：管理端「组织架构 → 新增顶级组织/新增下级」保存，toast 500；控制台 `Failed to load resource: 500 (Internal Server Error)`（`POST /api/admin/orgs`）。
- **根因**：`docker/init/001_schema.sql`（organizations 表 33–39 行）`id INTEGER PRIMARY KEY` 无自增；`admin_service.create_org`（308 行起）构造 `Organization(...)` 未显式传 id → 同 BUG-B1 机制。
- **复现**：新增顶级组织，名称 `E2E测试组织` → 500，节点数不变（13）。
- **修复建议**：同 BUG-B1。
- **影响面**：组织架构无法新增节点；编辑/删除/同步不受影响。

### BUG-B3【高】微信首次登录（无头像）500：`users.avatar NOT NULL` 遇上 `''=NULL`

- **接口**：`POST /api/auth/login`（微信 code 登录）
- **现象**：新用户首次登录且未携带头像时 HTTP 500（HTTP 直连复现；已登录用户不受影响）。
- **根因**：
  1. `docker/init/001_schema.sql`：`users.avatar VARCHAR(500) NOT NULL`；
  2. `backend/app/services/auth_service.py`：新用户 `avatar=avatar or ""`；
  3. openGauss A 模式 `''` 即 `NULL` → 违反 NOT NULL → IntegrityError → 500。
- **影响面**：任何未授权头像的微信新用户无法完成登录注册，属用户侧阻断性缺陷。
- **修复建议**：DDL 放开 `avatar` 的 NOT NULL（推荐，语义上“无头像”合法）；或代码侧使用非空占位串。同类排查建议：检查所有“空串默认值 + NOT NULL 文本列”组合。

### BUG-B4【中】`questions.analysis` 默认空串写入 NOT NULL 列（潜在 500）

- **接口**：`POST /api/admin/questions`（修复 BUG-B1 后必然暴露）
- **根因**：schema `analysis TEXT NOT NULL`；模型 `default=""`；schema `AdminQuestionUpsert.analysis: str = ""`（`schemas.py:315`）。openGauss A 模式下 `''=NULL` → 不填解析的新题目将 NotNullViolation。
- **证据**：显式 id=999、analysis='' 的 INSERT 复现 NotNullViolation（已清理测试数据）；analysis 非空时同语句成功。
- **修复建议**：`analysis TEXT NULL`（与业务语义一致）；或插入前把空串归一为占位文本。建议以此类推全库排查（`''` 默认值 × NOT NULL 文本列）。

### 4.5 低级 / 建议

1. **异常语义**：POST 类 500 均以 IntegrityError 形态暴露，未转义为业务错误提示；建议统一异常处理，避免向前端泄漏 SQL 细节。
2. **管理端删除确认文案**（`/orgs/{id}` DELETE）：返回 `[1, 4]` 为裸 id 列表，建议附带组织名，便于管理员理解。

## 5. 通过项明细（要点）

- **排名洞察**：累计/平均步数、达标率、完赛人数统计正确；前三名领奖台与 10 节点轨迹（瑞金→延安，0–65000 步）与 `route_nodes`、`lit_nodes`、`daily_sport` 聚合一致；组织筛选、搜索、CSV 导出（BOM、表头含 10 个点位列、公式注入防护 `csvCell`）全部通过；导出跟随当前筛选。
- **题库维护**：列表、题型筛选（判断题→5 条）、题干关键字搜索（仅按题干匹配，符合设计）、组合筛选、编辑全字段回显、删除（含确认框）、删除后 `daily_question` 引用清理。
- **组织架构**：树形展示（4 级 13 节点）、新增下级弹窗父节点预填、编辑防环（el-tree-select 自身/子孙禁用，DOM `aria-disabled` 验证）、删除保护（被引用节点+祖先保留）、seed 同步全量对齐（按 id upsert + 无引用清理）。
- **鉴权**：除 `/api/admin/login` 外，被测接口未携带/携带无效 token 时均 401（管理端路由守卫 + `get_current_admin` 依赖）。
