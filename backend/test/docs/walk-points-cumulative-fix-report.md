# 步行积分累计口径修复测试报告

## 问题原因

- 「我的」页累计运动步数来自 `daily_sport.steps` 实时汇总，步行积分来自 `points_log` 步行台账汇总。
- V2.0 的 `017_points_ledger.sql` 曾按「每天各自取整」回填步行积分；后续 019 已改为累计结余口径，但应用启动没有基于运动源数据修复历史台账。
- 如果部署库未执行或未完整执行 019，跨日零碎步数（如 500 + 500 + 1611）会显示累计 2611 步但步行积分 1 分。

## 修复内容

- `points_service.recompute_walk_all(db, fix=True)`：按 `daily_sport` 分批重算全部用户的步行台账，只修复 walk 来源，不修改答题积分和 legacy 流水。
- FastAPI 启动时执行步行积分修复；该逻辑基于源数据覆盖，重复启动不会重复加分。
- 每日最多 20000 步参与计分的规则保持不变。

## 计算示例

| 历史运动 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 500 + 500 + 1611 = 2611 步 | 0 + 0 + 1 = 1 分 | floor(2611 / 1000) = 2 分 |
| 1500 + 1111 = 2611 步 | 结余口径为 2 分 | 2 分 |
