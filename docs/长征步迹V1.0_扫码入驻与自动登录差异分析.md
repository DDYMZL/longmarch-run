# 长征步迹 V1.0：通用二维码扫码入驻与自动登录 —— 差异分析与改造方案

> 日期：2026-10-11
> 说明：本文替代《身份绑定与自动登录改造分析报告》中的员工名册/手机号验证/绑定码方案。V1.0 仅实现「通用二维码入口 + 微信身份自动登录」，员工身份绑定等后续功能不在本期开发（相关半成品代码已搁置，未合入）。

## 1. 现状核查结论

| 环节 | 当前实现（代码位置） | 与 V1.0 需求的差异 |
| --- | --- | --- |
| 登录接口 | `POST /api/auth/login`（`backend/app/api/routes/auth.py`）：code → `code2session` → openid → 查/建用户 → 签发 JWT（`sub`=用户 id，7 天） | 接口、JWT 格式、用户表可直接复用 ✅ |
| openid 唯一性 | `users.openid` 唯一索引（`models.User`） | 已满足 ✅ |
| 微信失败处理 | `auth_service.wx_login`：`code2session` 失败时**无条件回退 mock openid** | ❌ 已配置微信凭证时，微信失败会被当成 mock 用户登录成功，产生"假登录"脏用户。需改为：仅未配置 `WX_APPID/WX_SECRET`（本地开发）才用 mock，已配置时返回 502 |
| 并发首登 | 先查后插，未处理唯一约束冲突 | ❌ 同一 openid 并发首登时第二个请求 `IntegrityError` → 500。需捕获后回滚并重查已存在用户 |
| 重复登录 | 只在传入头像时更新 `avatar`，昵称/组织/步数/答题/勋章不动 | 已满足"不覆盖业务数据" ✅（静默登录不传头像，不会清空头像） |
| Token 校验接口 | `GET /api/auth/me`（`get_current_user`：解码 JWT + 查用户存在） | 可直接复用为"后端校验 Token" ✅ |
| 小程序启动 | `app.js onLaunch` 仅凭本地 `user + token` 即判定已登录 | ❌ 违反"不得仅凭本地 Token 判定有效"；无启动校验 |
| 小程序登录方式 | 登录页需点击「微信授权登录」（chooseAvatar）后才登录 | ❌ 首次扫码不能直接进首页，多一步操作 |
| 首次登录引导 | 登录后无组织强制跳组织选择页；home/march/quiz/rank/mine 均强制跳转 | ❌ 违反"扫码后直接进入首页、不增加额外步骤"。后端各组织接口对无组织用户已返回空结构（`org_service` 114/147/200 行），首页组织卡片 `wx:if="{{orgName}}"` 自动隐藏，可安全取消强制 |
| Token 过期 | `request.js` 收到 401 → 清登录态并 `reLaunch` 登录页 | ❌ 需改为静默 `wx.login` 重新登录并重试原请求 |
| 网络异常 | 请求失败 reject 文案提示，无重试入口 | ❌ 启动阶段需"网络异常提示 + 重试"，且网络异常不得清除登录态 |
| 二维码 | `wechat_service.get_wxacode_png(scene)` 已封装 getwxacodeunlimit，但页面写死 `pages/bind/bind`（PC 扫码登录确认页） | 复用该能力，参数化 page；新增入驻二维码接口与后台下载入口 |
| 管理端权限 | 管理接口统一 `get_current_admin`（要求 `role=admin`）；小程序 Token 无 role 字段 | 普通用户 Token 无法访问管理接口 ✅；扫码只登录小程序，不涉及管理授权 ✅ |
| 受保护接口 | 业务接口统一依赖 `get_current_user` | 已满足 ✅（测试中逐一枚举验证） |

## 2. 改造方案（最小改动，复用现有体系）

### 2.1 后端
1. `auth_service.wx_login`
   - 已配置微信凭证且 `code2session` 失败 → 抛 `WxLoginError`，路由转 **502「微信登录失败，请重试」**，不建用户、不签发 Token；
   - 未配置凭证（本地开发）保持 mock openid 行为不变；
   - 新建用户捕获 `IntegrityError` → 回滚 → 按 openid 重查返回已存在用户（并发首登不重复建号、不报错）。
2. `wechat_service.get_wxacode_png(scene, page=...)` 参数化页面，PC 扫码登录调用不变。
3. 新增 `GET /api/admin/onboarding-qrcode`（`get_current_admin`）：生成通用入驻小程序码，页面 `pages/launch/launch`，固定 scene `src=onboard`（仅渠道标记，不含任何个人信息/OpenID/Token）。成功结果进程内缓存；未配置凭证时返回 mock 标记。
4. **无数据库变更**：复用 `users` 表与 openid 唯一索引。

### 2.2 管理后台
- 顶栏新增「入驻二维码」入口，弹窗展示小程序码并支持下载 PNG；mock 模式提示"未配置微信凭证"。

### 2.3 小程序
1. 新增启动页 `pages/launch/launch` 并设为 `app.json` 首页面（也是入驻二维码落地页）：展示加载态 → `auth.ensureLogin()` → 成功 `switchTab` 首页（带 `redirect` 时回原页，兼容 PC 扫码登录确认页）。
2. `auth.ensureLogin()`（单飞，同一时刻只有一个登录流程）：
   - 有 Token → `GET /auth/me` 后端校验：有效则刷新本地用户并进入；401 → 静默登录；
   - 无 Token / Token 失效 → `wx.login` → `POST /auth/login` → 保存 Token 与用户；
   - `wx.login` 或后端登录失败 → 清理失效登录态、保持未登录，页面展示错误 + 重试；
   - 网络异常 → 不清本地登录态，展示"网络异常，请检查网络后重试" + 重试按钮。
3. `app.js`：启动时 `loggedIn=false`，只有后端校验通过后才置为已登录。
4. `request.js`：401 时调用注册的静默重登处理器（单飞）后**重试原请求一次**；重登失败才清理登录态并回到启动页。
5. 各页面登录守卫改为 `reLaunch` 启动页；取消 home/march/quiz/rank/mine 及登录页的"无组织强制选择"，组织在「我的」页可选填。
6. 保留登录页作为"退出登录后手动重新登录"入口（退出后不会被自动登录，符合用户主动退出的预期）。

### 2.4 不在本期范围（明确不做）
手机号验证、短信、工号/姓名/手机号校验、个人绑定码、人工审核、名册关联、组织身份校验、员工名册导入与绑定。

## 3. 安全设计
- 二维码只含页面路径与固定渠道标记 `src=onboard`，不含 OpenID、JWT 或个人信息；
- 小程序代码中无固定 Token，code 换取 openid、建用户、签发 Token 全部在后端完成；
- 小程序 Token 不含 `role=admin`，管理接口一律拒绝；入驻二维码接口本身仅管理员可调用；
- 保留管理员账号、RBAC 菜单权限与业务数据隔离规则不变。

## 4. 已知限制与风险
- 微信不保证 `wx.login` 在弱网下成功，启动页以"提示 + 重试"兜底；
- 每日登录积分 `points_service.grant` 为"先查后插"，极端并发同日首登可能重复记 1 分（不影响用户唯一性与其他业务数据），本期不加迁移，后续可补 `(user_id, date, reason)` 唯一约束；
- 入驻二维码需真实 `WX_APPID/WX_SECRET` 与已上传含 `pages/launch/launch` 的版本（`WXACODE_ENV_VERSION` 对应体验版/正式版）才能真机扫码，需真机验收。

## 5. 测试计划（对应需求 11 项）
后端冒烟（SQLite + TestClient，mock 微信）覆盖：新用户首登、重复登录不重复建号、并发登录不重复建号、微信失败不签发 Token、业务数据不被覆盖、受保护接口未登录拒绝（枚举全部用户接口）、普通用户 Token 访问管理接口拒绝、入驻二维码仅管理员可取。
小程序侧（启动恢复、有效 Token 直达、过期自动重登、网络异常重试）以开发者工具 automator 验证，无法执行项在测试报告中标注"未执行/待验证"。
