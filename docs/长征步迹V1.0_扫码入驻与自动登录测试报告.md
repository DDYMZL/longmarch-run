- 范围：仅 V1.0。不含手机号/短信验证、工号/姓名校验、绑定码、人工审核、名册导入与绑定、组织身份校验

## 1. 结论

需求中的 11 个测试场景在**后端接口层**、**小程序登录状态机**和**开发者工具端到端**三层均已执行并通过，未发现阻断问题。

以下依赖真实环境的项目尚未执行，标为**待验证**，见第 5 节：
- 真机扫码入驻二维码；
- 真机断网/弱网；
- 在 openGauss 上回归。

## 4. 改动清单

### 4.1 接口变更

| 接口 | 变更 |
|---|---|
| `POST /api/auth/login` | 复用原接口，请求与响应结构不变。<br>• 已配置 `WX_APPID/WX_SECRET` 时 code 换取失败返回 **502**「微信登录失败，请重试」，不再回退 mock。<br>• 并发首登撞唯一约束时复用已有用户。<br>• 仅在传入头像时更新头像，昵称、组织、业务数据不覆盖。 |
| `GET /api/auth/me` | 不变；小程序启动页用它在后端校验本地 Token |
| `GET /api/admin/onboarding-qrcode` | **新增**，需管理员权限。返回 `{image, page:"pages/launch/launch", scene:"src=onboard", env_version, mock}`；成功结果按小程序版本进程内缓存；未配置凭证时 `mock=true`、`image=null` |
| `POST /api/admin/wechat/qr` | 行为不变；图片 data URL 改为按文件头识别 png/jpeg |

### 4.2 数据库变更

**无。** 复用现有 `users` 表；`users.openid` 已有唯一索引（`docker/init/001_schema.sql` 中的 `ix_users_openid`），并发防重依赖此约束。

### 4.3 配置变更

- `WX_LOGIN_ALLOW_MOCK`（默认 `false`）：仅供本地自动化测试，**生产必须为 false**。已写入 `backend/.env.example`。

## 5. 待验证与遗留风险

| 项目 | 说明 | 状态 |
|---|---|---|
| 真机扫码入驻 | 需上传含 `pages/launch/launch` 的体验版或正式版；`WXACODE_ENV_VERSION` 须与版本一致（当前为 trial，扫码者须为体验成员）。验收步骤：后台下载入驻码 → 新微信号扫码进入首页 → 关闭后重开自动登录 → 库中只有 1 个用户 | **待验证** |
| 真机网络异常 | 飞行模式或断网下打开小程序，应显示网络异常提示和「重新进入」；恢复网络后点击重试进入首页 | **待验证** |
| openGauss 回归 | Docker Desktop 当前未运行，本次测试均使用 SQLite 临时库。唯一约束行为在 openGauss 上同样成立（唯一索引已存在），仍需在 openGauss 上重跑 S13 | **待验证** |
| 每日登录积分并发 | 后端 `grant_daily_login` 为"先查后插"，同一用户极短时间内并发登录理论上可能重复发放 1 积分；前端已单飞合并登录，实际难以触发 | 已知风险，未修复 |
| 每日登录积分时机 | 本地 Token 有效时启动只调用 `/auth/me`，不发登录积分，与改造前"有效 Token 不重新登录"的行为一致 | 与原行为一致 |
| 寄语表为空 | `GET /api/quotes/today` 返回 500（响应模型不允许空值）；首页已容错，不影响登录 | 留待功能二（寄语导入与循环）修复 |
| 主动退出语义 | 退出后进入登录页手动登录，不自动登录（含扫码进入）；手动登录一次后恢复自动登录 | 设计如此 |
| 旧 automator 套件 | 旧脚本假设"无组织强制跳 org-select、直接 reLaunch 业务页"，需按新启动流程调整后再跑全量回归 | 待后续回归 |
| 密钥安全 | `WX_SECRET` 曾在 git 历史 `865aec4` 中泄露，建议在微信公众平台重置 | 建议处理 |
