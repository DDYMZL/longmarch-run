## 3. 修复内容（第一轮 4 个缺陷）

### 3.1 BUG-001 管理后台新建组织必失败（organizations 表主键无自增）

- **根因**：`organizations.id INTEGER PRIMARY KEY` 无自增序列，ORM 插入未指定 id 时向数据库写入 NULL 主键 → 500。
- **修复**：
  1. `docker/init/001_schema.sql`：`id INTEGER PRIMARY KEY` → `id SERIAL PRIMARY KEY`（新装库直接正确）；
  2. 新增迁移 `docker/init/009_org_serial.sql`：`CREATE SEQUENCE organizations_id_seq` + `ALTER TABLE ... ALTER COLUMN id SET DEFAULT nextval(...)` + `setval` 到当前最大 id；已应用到运行库并登记 `schema_migrations`（存量库修复）；
  3. `admin/src/views/OrgsView.vue`：`handleSave` 增加 `catch`——请求失败时错误提示由 axios 拦截器统一弹出（ElMessage），弹窗保持打开便于修改重试，不再出现未捕获异常。
- **验证**：e2e D11/D12/D13 通过（新增/修改/落库）；API 探针新建组织 200（返回 id=17）；浏览器 UI 实测创建成功（见 §6.3）。

### 3.2 BUG-002 答题提交不校验题目归属当日抽题

- **根因**：`quiz_service.submit` 只校验「当日是否已提交」，不比对 answers 的 question_id 与当日抽题集合。
- **修复**：`backend/app/services/quiz_service.py` 的 `submit` 增加两道校验：
  1. 当日抽题缓存（daily_questions）不存在 → 400「今日题目尚未生成，请先获取题目」；
  2. 任一 question_id 不属于当日抽题集合 → 400「提交的答案包含不属于今日抽题的题目」。
- **验证**：e2e E09（非当日题目 400）、E10（被拒绝的提交不占用当日答题机会）通过；API 探针两种场景均 400；正常答题流程无回归（e2e Q 阶段全过、automator 阶段 3 满分/零分提交均通过）。

### 3.3 BUG-003 手动补步无下限校验

- **根因**：`AddStepsRequest.delta: int = 0` 无 `ge=0` 约束，负数直接叠加写入 daily_sport。
- **修复**：`backend/app/schemas/schemas.py`：`delta: int = Field(0, ge=0)`，负数请求被 FastAPI 以 422 拒绝（detail 含 `greater_than_equal` 校验信息）。
- **验证**：e2e E11（负数 422）、E12（拒绝后步数不变）、E13（拒绝后 DB 与 API 一致）通过；API 探针 -100000 → 422。

### 3.4 BUG-004 驾驶舱 WS 实时动态时间戳格式不一致导致渲染崩溃

- **根因**：WS `at` 为毫秒数字时间戳（`_now_ms()`），REST `event_time` 为 ISO 字符串；`formatTime` 对数字执行 `new Date("1791448682843Z")` 得到 Invalid Date → `Intl.DateTimeFormat.format` 抛 RangeError → DashboardView render 崩溃、数据冻结。
- **修复**：`backend/app/core/ws.py`：`_now_ms()` 替换为 `_now_iso()`（`datetime.utcnow().isoformat()`），`data_changed` 与 `activity` 两类消息的 `at` 统一为 ISO 字符串，与 REST `event_time` 契约一致（formatTime 已有对无时区 ISO 的处理约定）。
- **验证**：WS 探针实测两类消息 `at` 均为 ISO（如 `2026-10-08T10:47:34.805614`）；浏览器实测驾驶舱实时刷新正常、控制台零错误（见 §6.3）；e2e 新增 W03 断言（广播 at 为 ISO 字符串）通过，防止回归。

   - BUG-001：数据库 DDL 迁移（存量库）+ 建表语句（新库）双修复，admin 新建组织 UI/API 双层验证成功；
   - BUG-002：非当日题目提交被 400 拒绝且不占用当日答题机会；
   - BUG-003：负数补步 422 拒绝、步数与 DB 不受影响；
   - BUG-004：WS 时间字段统一 ISO 契约，驾驶舱实时刷新恢复且控制台零错误。
2. **无回归**：后端 e2e 176/176 全绿；automator 阶段 1-3 全过、阶段 4-5 通过部分与第一轮一致（差异均为已知套件资产/环境问题，非产品功能变化）；截图巡礼 16/16（优于第一轮 13/16）。
3. **无新缺陷**：复测轮未发现新的产品缺陷；修复-复测循环满足「直到没有 bug」的终止条件。
4. **数据面**：业务数据从全新状态起步，负步数污染已清除；页面 → API → 数据库三层核对一致。
5. **遗留**：仅测试资产维护（ui-test.cjs 菜单索引、T16a 模拟器环境限制）与真机覆盖两项，不影响产品验收结论。
