# .env.development

## 1. 文件路径
`admin/.env.development`（实测 3 行）

## 2. 文件职责
管理后台**本地开发环境**（`npm run dev`）的环境变量文件。Vite 在 `development` 模式下加载它，`admin/vite.config.ts:5` 的 `loadEnv(mode, '.', '')` 读出其中的 `VITE_API_PROXY`，作为 dev server `/api` 反向代理的上游地址（`admin/vite.config.ts:13`）。当前约定为**指向本机后端**。

> **本文档只记录配置项名称、行号与用途，不复制任何实际值**（`.qoder/README.md` §3.14、§4「敏感配置」行）。

## 3. 业务需求
- **本地开发默认连本机后端**：`761d860`（2026-10-16）确立「双环境文件」约定——`npm run dev` 连本地后端、`npm run dev:prod` 连远程后端（`.qoder/admin/.env.prod.md`）。此前（`ad1d747`～`527db98`，2026-10-13～10-14）方向**相反**：本文件默认指向远程，需另建 `.env.development.local` 覆盖才连本机。旧约定已废弃，勿再按旧口径描述。
- **免跨域、免改前端代码**：管理后台统一用相对路径 `/api` 发请求（`admin/src/api/request.ts:14-17` 的 `baseURL: '/api'`），环境差异全部落在本文件 + `admin/vite.config.ts` 的代理层，浏览器代码里不出现任何后端主机名，同一份构建产物可部署到任意环境。
- **局域网验收**：`admin/vite.config.ts:9` 的 `host: true`（`18a8848`，2026-10-10）让他人可用「本机 IP:5173」访问管理后台，其接口仍由本机 dev server 代理到本文件指定的上游，访问者无需改任何地址。
- **入库状态**：本文件**已被 git 跟踪**（`git ls-files admin` 实测命中）。根 `.gitignore` 的 `.env` 模式只匹配名为 `.env` 的文件、`.gitignore:12` 的 `.env*.local` 只匹配 `.local` 后缀，故本文件不在忽略范围内。`.qoder/PROJECT.md` §9「已被 git 跟踪（入库）」将其敏感度评为**低：仅 API 代理地址，无凭据**。

## 4. 核心功能

### 4.1 文件结构
共 3 行：2 行注释（`:1-2`）+ 1 个配置项（`:3`）。`KEY=VALUE` 形式，无分节标题、无引号、无 `export` 前缀。

| 行 | 内容类型 | 说明 |
|---|---|---|
| `:1` | 注释 | 标明生效命令：本文件供 `npm run dev` 使用 |
| `:2` | 注释 | 标明消费方与用途：Vite dev server 将 `/api` 代理到该地址 |
| `:3` | 配置项 | `VITE_API_PROXY` |

### 4.2 配置项清单

| # | 行号 | 配置项 | 用途 | 敏感性 |
|---|---|---|---|---|
| 1 | `:3` | `VITE_API_PROXY` | Vite dev server `/api` 代理的**上游后端基地址**（协议 + 主机 + 可选端口，不含路径）。当前约定指向**本机后端**（回环地址 + 后端本地监听端口），与 `admin/vite.config.ts:13` 的 `||` 回退默认值等价 | **非机密**：只是地址，不含账号/口令/密钥/Token。仍按规则不抄原值 |

**这是本文件唯一的配置项。** 两份 env 文件（本文件与 `.env.prod`）的键集完全相同、只有一项，差异仅在**值的语义**（本地 vs 远程），不存在「本地有、生产缺」的键差。

### 4.3 值的语义（不抄原值）
- 本文件的值指向**本地回环地址上的后端端口**，即开发者本机由 `backend/run.py` 启动的 FastAPI 服务。
- 与 `admin/.env.prod:4` 的值（指向**远程已部署后端的 HTTPS 域名**，走默认 443）形成对照。
- 若本文件被删除或该项被注释掉，`admin/vite.config.ts:13` 的 `||` 回退会取到与当前值等价的本地默认地址，**行为不变且不报错**——因此「误删本文件」在本地开发场景下是静默的（见 §9）。

## 5. 输入与输出
- **输入格式**：纯文本 `KEY=VALUE`，Vite 内部用 dotenv 解析；`#` 起行为注释；值无需引号。
- **被谁读取、何时读取**
  | 读取方 | 时机 |
  |---|---|
  | `admin/vite.config.ts:5` 的 `loadEnv(mode, '.', '')` | 每次执行 `vite` / `vite build` / `vite preview` 时，在配置求值阶段读取。第三参为空串 → 不按 `VITE_` 前缀过滤，文件内所有键都会被读入返回对象 |
  | Vite 自身的 env 注入机制 | 仅把 `VITE_` 前缀的变量注入客户端代码（`admin/vite.config.ts` 未改 `envPrefix`）。但 **`admin/src` 内实测无任何 `import.meta.env` 使用**，故本文件的值**只被 Node 侧的 `vite.config.ts` 消费，不会进入构建产物** |
- **加载优先级**（Vite 标准行为）：`.env.development.local` > `.env.development`（本文件）> `.env`。仓库内**不存在** `admin/.env`；`.env.development.local` 被 `.gitignore:12` 忽略，属本机私有覆盖，**不建档**（`.qoder/README.md` §4「本机私有配置」行）。
- **mode 匹配**：本文件只在 mode 为 `development` 时加载，即 `npm run dev`（`admin/package.json:7`，未指定 `--mode`，Vite dev 默认 `development`）。`npm run dev:prod` 与 `npm run build` 用 `--mode prod`，加载的是 `admin/.env.prod`，**不读本文件**。
- **输出**：无产物；解析结果只存在于 Vite 进程内存中，用作 `admin/vite.config.ts:13` 的代理目标。
- **异常形态**：值拼错（如缺协议头、端口写错）不会在启动时报错，表现为代理请求 502/ECONNREFUSED；文件缺失则静默走回退默认值。

## 6. 依赖关系
**依赖的外部资源**
- 本机后端服务：`backend/run.py` 启动的 FastAPI，监听端口须与本文件的值一致（该端口同时是 `admin/vite.config.ts:13` 的回退默认值，也是 `.qoder/PROJECT.md` §4「端口与环境变量」记录的后端端口）。
- 后端本地库由 `docker/compose.yml` 启动的 openGauss 容器提供（详见 `.qoder/backend/.env.md`）。

**必须与哪些文件保持一致**
| 文件 | 一致性要求 |
|---|---|
| `admin/vite.config.ts:13` | 键名必须是 `VITE_API_PROXY`；回退默认值应与本文件的值语义一致（同为本地后端），否则「有 env」与「无 env」两种状态会连到不同上游 |
| `admin/package.json:7` | `dev` 脚本**不得**带 `--mode`，否则本文件不被加载 |
| `admin/.env.prod` | 键集需保持一致（当前均为单键 `VITE_API_PROXY`）；新增键时应同时评估是否加进对方，避免出现单环境缺配置的静默差异 |
| `admin/src/api/request.ts:14-17` | `baseURL: '/api'` 必须与 `admin/vite.config.ts:12` 的代理前缀一致，本文件的值只提供主机部分、**不得带 `/api` 路径后缀**（否则会变成 `/api/api/...`） |
| `admin/src/utils/liveUpdates.ts:61-62` | WS 地址由 `location.host` + `/api/ws/updates` 拼出，同样走本文件指定的上游；代理规则的 `ws: true`（`admin/vite.config.ts:15`）保证升级请求被转发 |
| 后端 `API_PREFIX` 与 CORS 配置 | 本地走代理时浏览器看到的是同源 `5173`，CORS 不参与；一旦把本文件的值直接暴露给浏览器（例如改成前端直连），就必须核对 `backend/.env` 的 `CORS_ORIGINS` |

**同族文件**：`admin/.env.prod`（生产/联调，4 行，同为单键）。`.env.development.local`（本机私有覆盖，gitignore，不建档）。

## 7. 业务规则
无——本文件只承载配置项，不含积分、权限、状态流转等业务规则。它承载的**工程约定**：

1. **一命令一环境**：`npm run dev` ↔ 本文件（本地后端）；`npm run dev:prod` ↔ `admin/.env.prod`（远程后端）。两者不得混用，也不得靠改本文件来「临时连生产」——那正是 `dev:prod` 存在的理由。
2. **环境差异只落在代理层**：业务代码永远用相对路径 `/api`，因此切换环境**不需要重新构建**、也不会把后端主机名带进产物。
3. **本文件的值不进入构建产物**：`npm run build` 用 `--mode prod`，根本不读本文件；即便读了，`admin/src` 内也无 `import.meta.env` 消费点。

## 8. 修改约束
- **文件名不可改**：`admin/.env.development` 是 Vite 对 `development` 模式的**约定文件名**（`.env.[mode]`）。改名（例如改成 `.env.dev`、`.env.local`）会让 `npm run dev` 静默读不到它，并回退到 `admin/vite.config.ts:13` 的默认值——不报错，只表现为「改了没生效」。
- **不要把本文件的键复制到 `admin/src` 代码里直接用**：凡 `VITE_` 前缀的变量都会被注入客户端产物、等同公开。当前只有 Node 侧的 `vite.config.ts` 读它，这个边界不要打破。
- **禁止写入任何凭据**：本文件已入 git 历史（含 `ad1d747`、`1e2d53b`、`527db98`、`761d860` 四个提交），写入的值会永久留存。历史上本文件**只出现过 `VITE_API_PROXY` 一个键**（经 `git log -p` 全量核对，无口令/密钥/Token），该干净状态需保持。
- **值只写「协议 + 主机 + 可选端口」，不带路径**：路径部分由 `admin/vite.config.ts:12` 的 `/api` 前缀与 `admin/src/api/request.ts:15` 的 `baseURL` 承担。
- **改端口须与后端实际监听端口同步**：后端端口若变更，本文件与 `admin/vite.config.ts:13` 的回退默认值需一起改，否则「有 env」和「无 env」两种状态行为分叉。
- **临时切换上游请用 `.env.development.local` 或 `npm run dev:prod`，不要改本文件后忘记改回**：本文件是入库文件，改动会产生提交噪声；`.env.development.local` 已被 `.gitignore:12` 忽略，正是为此设计（但**不建档**）。
- **注释是本文件的主要文档载体**：`:1-2` 明确了生效命令与消费方，修改配置项时应同步更新注释（历史上 `ad1d747` 版本的注释描述的是「默认远程 + `.local` 覆盖连本机」，与 `761d860` 后的实际约定相反，已随该提交一并更正）。
