# .env.prod

## 1. 文件路径
`backend/.env.prod`

## 2. 文件职责
后端**生产环境**的实际生效配置文件。仅当系统环境变量 `APP_ENV=prod` 时由 `backend/app/core/config.py:15` 选中加载；其余情况加载 `backend/.env`。本文件随 `backend-update.tar.gz` 发布到服务器（`:1` 注释）。

> **本文档只记录配置项名称、行号与用途，不复制任何实际值**（`.qoder/README.md` §3.14）。文件中多处标注「⚠ 占位」，其占位内容同样不录入本文档。

## 3. 业务需求
- 生产与本地配置分离：`f05531a`（2026-10-16）新增本文件，同时引入 `APP_ENV` 切换加载机制。此前生产配置只能靠服务器环境变量逐项注入，易漏且不可追溯。
- 生产环境的安全基线：`DEBUG=false`（`:60` 注释「生产必须 false」）、`WX_LOGIN_ALLOW_MOCK=false`（`:21` 注释「生产必须 false」）、小程序码用正式版 `release`（`:24` 注释「扫码者无需体验成员权限」）、微信凭证禁止留空（`:18` 注释）。
- **入库决策**：根 `agents.md` §1.3 明确本文件经用户决定入库。`.gitignore:7` 的 `.env` 模式**不匹配** `.env.prod`（`.gitignore:9` 注释说明了这一点），故无需额外放行规则。

## 4. 核心功能

### 4.1 加载方式（`:2-4` 注释所载）
- 服务器上须设置**系统环境变量** `APP_ENV=prod`，例如 systemd unit 中写 `Environment=APP_ENV=prod`。
- **不能把 `APP_ENV` 写进本文件**——env 文件选择发生在解析 env 文件之前（`backend/app/core/config.py:12-13`），写进文件不生效。

## 5. 输入与输出
- **输入**：纯文本 `KEY=VALUE`，UTF-8（`backend/app/core/config.py:20`）。
- **输出**：仅在 `APP_ENV=prod` 时被解析进 `Settings` 单例。加载优先级「系统环境变量 > 本文件值 > 字段默认值」——**服务器上的系统环境变量可以覆盖本文件**，排查生产配置问题时须同时检查两处。
- **未知键**：`extra="ignore"` 静默忽略。经核对本文件 26 个键全部对应 Settings 字段，无冗余键。
- **异常**：`DATABASE_URL` 缺失即启动失败（`backend/app/core/config.py:31`）。

## 6. 依赖关系
- **被谁读取**：仅 `backend/app/core/config.py:15`、`:20`。
- **打包与发布**：`build-backend.bat:16` 的排除项是 `--exclude=.env`，**精确匹配 `.env` 而不匹配 `.env.prod`**；`:26` 的产物校验用 `findstr /e /c:".env"`（行尾匹配），同样不会命中 `.env.prod`。因此**本文件会被打进 `backend-update.tar.gz`**，与 `:1` 注释「随 backend-update.tar.gz 发布到服务器」一致，属有意设计。相对地 `backend/.env` 被排除、不上服务器。
- **同族文件**：`backend/.env`（本地实际配置，`APP_ENV` 非 `prod` 时加载）。原第三个同族文件 `backend/.env.example`（本地开发模板，25 键）已于 2026-10-17 删除——`.env` 既已入库，模板即冗余。
- **依赖的外部资源**：生产 openGauss（端口 5432）、微信服务端、腾讯云 CloudBase Agent、`ORG_SYNC_API_URL` 指向的组织架构外部同步接口。

## 7. 业务规则
- **`APP_ENV` 是唯一开关**：未设置或设为除 `prod` 外的任何值，都会加载 `backend/.env`。服务器上忘记设置 `APP_ENV=prod` 会导致后端**静默读取本地开发配置**（若 `.env` 也随包上了服务器）或因缺 `DATABASE_URL` 启动失败（`.env` 被打包脚本排除，故实际是后者）。
- **生产安全基线为强制项**：`DEBUG=false`（`:60`）、`WX_LOGIN_ALLOW_MOCK=false`（`:21`）、`WXACODE_ENV_VERSION=release`（`:24`）、`WX_APPID`/`WX_SECRET` 非空（`:18`）。前三项若配置错误，代码层**不会拦截**，只表现为行为异常（如出体验版码导致非体验成员扫不开）。
- **`JWT_SECRET` 必须与本地不同**（`:11` 注释）：否则本地签发的令牌在生产可用，构成越权风险。
- **`ADMIN_PASSWORD` 留空是合法的加固选择**（`:37` 注释）：留空时 `backend/app/api/routes/admin.py:108` 返回 403 禁用账号登录，仅允许微信扫码登录。
- **运行期改本文件不生效**：`lru_cache` + 模块级单例（`backend/app/core/config.py:110-115`），改完须重启后端进程。

## 8. 修改约束
- **5 处 `⚠` 占位项在部署前必须替换为服务器真实值**（`:5` 注释总述）：`DATABASE_URL`（`:8`）、`JWT_SECRET`（`:11`）、`ADMIN_PASSWORD`（`:37`）。**替换后的真实值不得提交回仓库**——本文件已入库，任何写入都会永久留存于 Git 历史。根 `agents.md` §1.3 对此有明确提示。
- **不得把生产真实凭证写入本文件的入库版本**；生产侧的真实值应通过服务器环境变量注入（优先级高于本文件，见 §5），或在服务器上就地修改而不回传仓库。
- 新增配置项须同步评估两个 env 文件（本文件、`backend/.env`），避免「本地能跑、生产缺配置」。
- 不得删除 `DEBUG`、`WX_LOGIN_ALLOW_MOCK` 两项——它们是生产安全基线的显式声明，删除后会退回 `backend/app/core/config.py` 的默认值（`DEBUG` 默认为 `True`，对生产不安全）。
- `CORS_ORIGINS` 收紧为具体域名前，须确认管理后台与小程序的实际请求来源，否则会引发跨域失败。
