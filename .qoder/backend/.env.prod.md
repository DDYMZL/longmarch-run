# .env.prod

## 1. 文件路径
`backend/.env.prod`

## 2. 文件职责
后端**生产环境**的实际生效配置文件。仅当系统环境变量 `APP_ENV=prod` 时由 `backend/app/core/config.py:15` 选中加载；其余情况加载 `backend/.env`。本文件随 `backend-update.tar.gz` 发布到服务器（`:1` 注释）。

> **本文档只记录配置项名称、行号与用途，不复制任何实际值**（`.qoder/README.md` §3.14）。文件中多处标注「⚠ 占位」，其占位内容同样不录入本文档。

## 3. 业务需求
- 生产与本地配置分离：`f05531a`（2026-10-16）新增本文件，同时引入 `APP_ENV` 切换加载机制。此前生产配置只能靠服务器环境变量逐项注入，易漏且不可追溯。
- 生产环境的安全基线：`DEBUG=false`（`:91` 注释「生产必须 false」）、`WX_LOGIN_ALLOW_MOCK=false`（`:21` 注释「生产必须 false」）、小程序码用正式版 `release`（`:24` 注释「扫码者无需体验成员权限」）、微信凭证禁止留空（`:18` 注释）。
- **AI 上游的生产口径**：`:48-49` 就地标注「⚠⚠ 上线部署前必须把本行改为 `LLM_PROVIDER=openai`」——生产应走阿里云百炼（按量计费、通用地址公网可达、支持关思考压时延），`cloudbase` 仅为当前开发/联调期临时口径。`:50` 当前值仍是 `cloudbase`，见 §9。
- **入库决策**：根 `agents.md` §1.3 明确本文件经用户决定入库。`.gitignore:7` 的 `.env` 模式**不匹配** `.env.prod`（`.gitignore:9` 注释说明了这一点），故无需额外放行规则。

## 4. 核心功能

### 4.1 加载方式（`:2-4` 注释所载）
- 服务器上须设置**系统环境变量** `APP_ENV=prod`，例如 systemd unit 中写 `Environment=APP_ENV=prod`。
- **不能把 `APP_ENV` 写进本文件**——env 文件选择发生在解析 env 文件之前（`backend/app/core/config.py:12-13`），写进文件不生效。

## 5. 输入与输出
- **输入**：纯文本 `KEY=VALUE`，UTF-8（`backend/app/core/config.py:22`）。`LLM_EXTRA_BODY`（`:61`）、`LLM_QUESTION_EXTRA_BODY`（`:63`）、`CORS_ORIGINS`（`:89`）三项的值是 JSON 字面量，由 pydantic 解析为 `Dict` / `List`。
- **输出**：仅在 `APP_ENV=prod` 时被解析进 `Settings` 单例。加载优先级「系统环境变量 > 本文件值 > 字段默认值」——**服务器上的系统环境变量可以覆盖本文件**，排查生产配置问题时须同时检查两处（尤其 `LLM_PROVIDER`：若服务器环境变量另设了值，本文件 `:50` 的取值就不是生效值）。
- **未知键**：`extra="ignore"` 静默忽略。经核对本文件 33 个键全部对应 Settings 字段，无冗余键。已随 `b712d81` 移除的 `CLOUDBASE_TIMEOUT_SECONDS` 若被误加回本文件，也会被静默忽略而不报错。
- **异常**：`DATABASE_URL` 缺失即启动失败（`backend/app/core/config.py:33`）。AI 侧配置缺失不阻止启动，只在调用时报错（见 §7）。

## 7. 业务规则
- **`APP_ENV` 是唯一开关**：未设置或设为除 `prod` 外的任何值，都会加载 `backend/.env`。服务器上忘记设置 `APP_ENV=prod` 会导致后端**静默读取本地开发配置**（若 `.env` 也随包上了服务器）或因缺 `DATABASE_URL` 启动失败（`.env` 被打包脚本排除，故实际是后者）。
- **生产安全基线为强制项**：`DEBUG=false`（`:91`）、`WX_LOGIN_ALLOW_MOCK=false`（`:21`）、`WXACODE_ENV_VERSION=release`（`:24`）、`WX_APPID`/`WX_SECRET` 非空（`:18`）。前三项若配置错误，代码层**不会拦截**，只表现为行为异常（如出体验版码导致非体验成员扫不开）。
- **`LLM_PROVIDER=openai` 同属上线强制项**（`:48-49` 注释以 ⚠⚠ 就地标注）：当前 `:50` 为 `cloudbase`，属开发/联调期临时口径。不改回则生产 AI 走 CloudBase Agent——功能可用，但流式首片延迟实测 8.6~16.7s（百炼 1.15~2.81s）、`max_tokens` 与思考开关在 ACP 下不生效（`:71-72` 注释）、`ai_usage_logs.used_tokens` 口径不可用于计费。代码层同样**不拦截**。
- **AI 凭证按 `LLM_PROVIDER` 取对应那套**：`openai` → `LLM_API_KEY`（`:58`，为空即在发请求前报「AI 服务未配置」）；`cloudbase` → `CLOUDBASE_API_KEY`（`:68`）+ `CLOUDBASE_ENV_ID`/`AGENT_ID`（`:66-67`，或 `CLOUDBASE_AGENT_URL` 非空）。未被选中的那套留空不影响启动与调用。`LLM_PROVIDER` 取值非法时 AI 接口返回 **502**，而 `model_label()`（写 `ai_usage_logs.model`）刻意不抛异常。
- **`JWT_SECRET` 必须与本地不同**（`:11` 注释）：否则本地签发的令牌在生产可用，构成越权风险。
- **`ADMIN_PASSWORD` 留空是合法的加固选择**（`:37` 注释）：留空时 `backend/app/api/routes/admin.py:108` 返回 403 禁用账号登录，仅允许微信扫码登录。
- **运行期改本文件不生效**：`lru_cache` + 模块级单例（`backend/app/core/config.py:142-147`），改完须重启后端进程。

## 8. 修改约束
- **部署前必改项**（`:5` 注释总述）：3 处 `⚠ 占位` 须替换为服务器真实值——`DATABASE_URL`（`:8`）、`JWT_SECRET`（`:11`）、`ADMIN_PASSWORD`（`:37`）；另有 1 处 `⚠⚠` 上线切换提示——`LLM_PROVIDER`（`:48-49` 注释、`:50` 值）。**替换后的真实值不得提交回仓库**——本文件已入库，任何写入都会永久留存于 Git 历史。根 `agents.md` §1.3 对此有明确提示。
- **上线切回阿里云百炼的三步**（出处 `backend/test/docs/s30-llm-provider-switch-report.md`）：① 在百炼控制台重置或新建 API Key（仓库内现存 `LLM_API_KEY` 已 401 失效，见 §9），替换 `:58` 一行；② 把 `:50` 改为 `LLM_PROVIDER=openai`；③ 跑 `python test/s30_llm_provider_switch.py`（D 组会真实调用）与 `s25`/`s26`/`s28` 回归。**无需改代码、无需数据库迁移、无需重新构建前端。**
- **不得为了「清理」而删掉当前未生效的那套 AI 凭证**：两套凭证常驻本文件是「切换供应商只改 `LLM_PROVIDER` 一行」这条约定的前提（`:45` 注释）。同理 **`CLOUDBASE_TIMEOUT_SECONDS` 不得恢复**（已由 `b712d81` 删除，与 `LLM_TIMEOUT_SECONDS`（`:52`）同义），**`AI_QUESTION_BATCH_SIZE`（`:79`）不得随供应商调整**（保持 `5`）。
- **不得把生产真实凭证写入本文件的入库版本**；生产侧的真实值应通过服务器环境变量注入（优先级高于本文件，见 §5），或在服务器上就地修改而不回传仓库。
- 新增配置项须同步评估两个 env 文件（本文件、`backend/.env`），避免「本地能跑、生产缺配置」。
- 不得删除 `DEBUG`、`WX_LOGIN_ALLOW_MOCK` 两项——它们是生产安全基线的显式声明，删除后会退回 `backend/app/core/config.py` 的默认值（`DEBUG` 默认为 `True`，对生产不安全）。
- `CORS_ORIGINS` 收紧为具体域名前，须确认管理后台与小程序的实际请求来源，否则会引发跨域失败。`PUBLIC_BASE_URL`（`:86`）变更同理，且须同步把新域名加入小程序 `downloadFile` 合法域名（`:84-85` 注释），否则他人头像加载失败。
